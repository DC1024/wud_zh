Localization

汉化内容：不是贴一层皮，是重做了一套 i18n

上游 WUD 的界面文案是硬编码在 17 个 Vue 文件里的英文串，没有任何 i18n 框架。 本分支引入了 vue-i18n v10，把散落的文案抽成两份键位对称的消息包，并接上了 Vuetify 的内置本地化。

语言包结构

两份消息包键位一一对应，改一处不会漏另一处。

zh-CN.ts简体中文消息包
en.ts英文消息包（值直接取自上游源码）
命名空间17 个（containers / watchlist / servers / config / hubMirrors …）
叶子键364 条（中英各 364）
index.ts默认语言、读写 wud-lang、同步 <html lang>

为什么值得重做 i18n

WUD 是那种"更新一多就得天天看"的工具 —— 容器列表、触发器状态、错误信息全在界面上。母语界面的价值不是好看，是看到 error 那一行的瞬间就能判断要不要动手。

  • 错误信息本地化：容器详情里的错误子页整页中文
  • 配置页汉化：触发器、监视器、服务器与系统配置
  • Vuetify 一并跟随：分页器、空状态、日期选择器都是中文
  • 可回退：切英文即回到上游观感，排障时可对照官方文档
Beyond upstream

相对原项目做的 5 项改进

汉化只是起点。下面这几条是上游当前版本没有、而中文用户几乎一定会撞上的问题 —— 尤其是国内出口访问不到 Docker Hub 这一条，会直接让 WUD 变成"全屏报错"。 所有改动都是纯增量：不改上游的环境变量、触发器与 REST API 行为。

① Docker Hub 镜像源可配置 + 多源 failover

上游把 Hub 地址硬编码为 registry-1.docker.io / auth.docker.io/token。国内出口这条链路会被 RST 重置（ECONNRESET），结果是所有 Docker Hub 容器整片报错、检测不了更新，而 GHCR、ECR 等其他源却一切正常 —— 这也是最难排查的一种"看起来是 WUD 坏了"。

环境变量作用何时需要
WUD_REGISTRY_HUB_URL仓库 API 基址（manifest / tags 拉取）想走镜像站时必填
…_AUTHURLtoken 端点匿名站不填；认证站填其 token 地址
…_SERVICEtoken 的 service 参数认证站且 service 非默认值时才填

默认值时与上游逐字一致，存量部署零影响。另提供网页版镜像列表编辑器：按顺序逐个试，第一个通的即生效，带连通性与鉴权类型探测。

② 监控清单：在网页上勾选要监控谁

上游只能靠 wud.watch 标签决定监控范围 —— 想改一个容器就得改 compose 再重建。本分支加了一个页面：在网页上直接勾，勾完点"立即生效"就下一次扫描生效。

优先级来源说明
1wud.watch 标签基础设施即代码，始终最高；打了标签的容器在页面上锁定
2网页勾选存库，键为 (watcher, 容器名) —— 按名字而非容器 ID，因为重建后 ID 会变
3watchbydefault都没设置才回落默认。库里没记录 ≠ false，否则老实例一升级就集体停止监控

新增两个纯增量接口：GET /api/containers/discover（列出全部容器含未监控）、PUT /api/containers/watch-preference。另支持批量勾选、孤儿偏好清理、未监控容器折叠。

③ 服务器管理页

跨机监控不再靠手拼环境变量。/configuration/watchers 升级为服务器列表（地址 / 端口 / 扫描计划 / 监控数 / 可达性），并带添加服务器三步向导：生成对端只读 socket 代理的 compose → 生成隧道账号与公钥 → 生成 wud.yaml 片段。删除也有对应引导。

④ 阿里云 ACR 匿名鉴权

上游的 Alibaba provider 只在配了凭据时才发 Basic，否则不带任何认证头、不走 Bearer 匿名流程 —— 而阿里云要求 Bearer，于是公开仓库也永远 401，检测不了更新。本分支自己实现 Bearer 握手：探测 /v2/ 取 realm → 换 token → 带 token 重放，兼容两种响应键；有凭据时仍转发 Basic 以支持私有仓库。

⑤ 通知与更新闭环

更新成功后自动回一封成功/失败邮件，含旧/新镜像 digest 与目标版本。并修掉了两个真实痛点：邮件正文里 digest 类更新会显示 (undefined) 的模板缺陷；以及"更新→重建→又更新"的自激循环（按容器名加冷却护栏 + 双判据成功检测）。

兼容承诺：升级只需换镜像名，回退也只需换回来。环境变量、触发器、卷映射、REST API 行为与上游完全一致； 后端新增部分（监控清单、镜像源列表）是纯增量的新表 + 新接口，不影响上游原有语义。

Get started

三行命令，把 WUD 换成中文

镜像公开托管在 GHCR，无需登录即可拉取。

docker run

bash
docker run -d \
  --name wud \
  -p 3000:3000 \
  -e WUD_AUTH_ADMIN_USER="admin" \
  -e WUD_AUTH_ADMIN_PASSWORD="MySecurePassword123" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  ghcr.io/dc1024/wud_zh:latest

Docker Compose（只改一行）

diff
 services:
   wud:
-    image: getwud/wud:latest
+    image: ghcr.io/dc1024/wud_zh:latest

国内出口推荐配置（绕过 Docker Hub 封锁）

yaml
services:
  wud:
    image: ghcr.io/dc1024/wud_zh:latest
    container_name: wud
    ports:
      - "3000:3000"
    environment:
      - WUD_AUTH_ADMIN_USER=admin
      - WUD_AUTH_ADMIN_PASSWORD=MySecurePassword123
      # --- Docker Hub 镜像：绕过出口封锁（匿名镜像站，无需 authurl）---
      - WUD_REGISTRY_HUB_URL=https://docker.1panel.live
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    restart: unless-stopped

镜像站可换任意信任的公共 / 私有 OCI 代理，只要它完整实现 manifest 与 tags/list。（选 1panel 而非 daocloud，是因为后者禁用了 tags/list，会破坏 semver 版本发现。）

发布与补翻

镜像自动构建

push 到 i18n-zh 后由 GitHub Actions 自动构建（约 1~3 分钟）并推送 GHCR，标签为 latest 与 sha-<commit>；也可在 Actions 页手动 Run workflow。

版本号规则

构建时把 WUD_VERSION 固定写入，界面显示为 wud_zh-beta1.4。规则：无新功能则维持，有实质更新则最后一位 +0.1（1.0 → 1.1 → 1.2 → 1.3 → 1.4）。

想补翻译？

在 zh-CN.ts 和 en.ts 里同时加键（两份必须键位对称）→ 把 .vue 里的硬编码文案换成 $t('命名空间.键') → 提交推送，CI 自动重建镜像。约定：en.ts 的值必须与上游原文逐字一致；中文按语义自然表达，不逐字直译。
